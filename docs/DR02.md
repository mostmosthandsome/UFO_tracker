# DR02 接入说明

本仓库通过 `--robot-config configs/robots/dr02_23dof.yaml` 加载 DR02，
不需要新增环境类，也不使用 `--robot dr02`。

模型来自 `whole_body_tracking` 中实际使用的 `dr02_pro.urdf` 和
`robots/dr02.py`：23 个受控关节（双腿 12、腰 3、双臂 8），浮动基座。
保留了固定腕部、颈部和头部，不采用 `dr02_pro_with_wrist.urdf`。

## 已迁移内容

- `ufo/data/robots/dr02/dr02_23dof.xml`：MuJoCo 模型及 meshes。
- 同目录的 `dr02_pro.urdf`：原始模型，用于来源记录和运动学对照。
- `configs/robots/dr02_23dof.yaml`：初始高度 0.93 m、源默认姿态、
  各关节 PD、力矩/速度限制和 armature；动作缩放为 0.25，关闭力矩/刚度二次缩放。
- `ufo/tools/dr02_import.py`：可复现的模型/配置和源 CSV 导入工具，无需 Isaac Lab。

MJCF 由 MuJoCo URDF 导入器生成，保留固定 body，添加浮动根关节和电机。
圆柱碰撞体转换为 capsule，与源项目的设置一致。关节上的
`actuatorfrcrange` 被移除，执行器限幅由 UFO/mjlab 管理。
脚对应 `left/right_ankle_x_link`，手端对应固定的 `left/right_wrist_x_link`，
躯干对应 `body`。

这是仿真迁移基线：源 Isaac Lab 使用隐式 PD，当前 UFO 使用 `dc_motor`，
速度相关力矩限制等动力学不完全等价；奖励、域随机化和训练算法使用 UFO 的配置，
并未移植源 PPO tracking 任务。还未验证真机或训练收敛。

## 准备动作数据

源 CSV 的列为根部 XYZ、四元数 XYZW、23 个关节。
**源 CSV 是腿优先，而生成 MJCF 是腰/手臂优先，不能直接把这些无表头 CSV
交给通用工具并假定为 XML 顺序。** 本导入器读取源
`scripts/csv_to_npz.py` 的关节列表，按名称重排后写成 RobotState NPZ。

本次本地接入已转换 `0-ceshoufan.csv`、`amass_cartwheel_49_06_poses.csv`，
生成 `configs/data/dr02_local.yaml`、`cache/dr02_robot_state/*.npz` 和完整/切片 PKL。
缓存不纳入版本控制，新机器需要重新执行以下步骤。

以下 `30` 来自源转换脚本默认值；CSV 本身没有时间列，因此它是待确认的采样率，
请按实际数据修改。该设置不会把源动作重采样成 50 FPS。

```bash
uv run python -m ufo.tools.dr02_import \
  --source /home/handsome/repo/handsome/research/whole_body_tracking \
  --force \
  --motion-source \
    /home/handsome/repo/handsome/research/whole_body_tracking/0-ceshoufan.csv \
    /home/handsome/repo/handsome/research/whole_body_tracking/amass_cartwheel_49_06_poses.csv \
  --fps 30
```

`--force` 会重新生成 DR02 模型、机器人 YAML 和动作清单/缓存；手工调参后不要
直接用它覆盖 YAML。只更新动作时，可在 Python 中调用 `import_motions`，或使用
通用 `motion_data` 工具导入已按名称标注的 RobotState NPZ。

## 验证与训练

先按仓库 README 用 `uv sync --locked` 安装正式 Python 3.10/CUDA 环境。

```bash
./run_train.sh --agent fb \
  --robot-config configs/robots/dr02_23dof.yaml \
  --data-manifest configs/data/dr02_local.yaml \
  --gpu-ids single --smoke --work-dir runs/dr02_smoke
```

`--smoke` 仅验证采样和保存；验证参数更新使用独立目录：

```bash
./run_train.sh --agent fb \
  --robot-config configs/robots/dr02_23dof.yaml \
  --data-manifest configs/data/dr02_local.yaml \
  --gpu-ids single --num-envs 16 --num-env-steps 24576 \
  --buffer-size 32768 --num-agent-updates 1 --disable-eval-prioritization \
  --work-dir runs/dr02_train_check
```

确认 `checkpoint/train_status.json` 的 `optimizer_steps > 0` 后，再配置正式训练预算。
两条侧手翻动作只适合做接入验证，正式训练需要更丰富的 DR02 重定向数据。
可将 `--agent fb` 换为 `--agent tech`；策略仍需重新训练。

数据构建命令会打印 `inference_paths`，跟踪推理时把其中完整动作 PKL 传给
`./run_inference.sh tracking --model-folder RUN --data-path FULL.pkl`。
完整动作和训练切片的 motion ID 不相同。

## 回归检查

```bash
uv run pytest tests/test_dr02_robot.py -q
```

检查 23 维布局和源控制参数、独立 URDF FK 与 MJCF FK 的一致性、
关节重排后 UFO FK 与 MuJoCo 的一致性，以及训练任务中的实际动作缩放。

本次验证：5 项 DR02 测试和 11 项既有模型/URDF 测试通过；RTX 3090 上
2 个环境完成重置和 16 步采样，观测/奖励均为有限值（关闭域随机化和观测噪声）。
两份 CSV 共 915 帧，未发现超出模型关节限位的角度。
验证使用 `/tmp/ufo-dr02-validation-venv` 中的 Python 3.12、PyTorch 2.5.1、
MuJoCo 3.11.0 和 mjlab 1.6.0；这是临时检查环境，未替代仓库锁定的正式训练环境，
也未执行优化器更新或完整训练。
